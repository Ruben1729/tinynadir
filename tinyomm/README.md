# tinyomm

A heap-free bounded CCSDS/GP decoded-field adapter and KVN subset for conventional SGP4. Required orbit/epoch/BSTAR fields are checked. Strict mode requires Earth/TEME/UTC/SGP4 metadata; an explicit CelesTrak GP defaults mode supplies those four documented omitted fields while rejecting supplied incompatible metadata. Versions 2.0/3.0 and ephemeris type 0 are supported. Raw JSON/XML/CSV decoding and complete CCSDS structural/schema validation are outside this profile.

Fields use the shared `tinytle_elements` type, retaining source degrees, revolutions/day and inverse-Earth-radius BSTAR units. Optional canonical numeric unit tags are checked (`deg`, `rev/day`, `1/ER`, `1`). Nine-digit catalog IDs are retained as metadata. ISO epochs use Gregorian years 1600–9999, optional fractional seconds and optional UTC Z; the uniform-day time profile rejects actual UTC leap-second instants. Initialization delegates to the SGP4 adapter without rounding through TLE text, verifies a finite epoch state and preserves the existing satellite on failure.

Numeric fields accept signs, decimal points and scientific notation. Leading zeros do not consume significant-digit capacity. Up to 19 significant decimal digits are retained, then converted to binary64 arithmetic. Trailing-zero normalization makes equivalent forms such as `1e-308`, `1.0e-308` and `1000000000000000000e-326` follow the same scaling path. Subnormal results are supported; values below half the minimum subnormal round to signed zero, and overflow is rejected. Exact decimal threshold comparisons protect overflow and minimum-subnormal boundary decisions. The conversion is bounded and locale independent; it does not claim correctly rounded conversion of every input. The exponent fixtures allow three binary64 ULPs.

Limits are 64 fields, 64 bytes per name, 128 bytes per value, 8192 KVN text bytes and 256 bytes per KVN line. Field buffers need not be terminated. Duplicate known fields are rejected; unknown metadata is ignored. All failed outputs are preserved. KVN field descriptors occupy 2048 stack bytes on a 64-bit ABI. There is no heap, mutable global state or runtime I/O.

## Verification

Independent python-sgp4 OMM initialization/propagation cases are frozen for numeric and nine-digit IDs, multiple orbit regimes, epoch fractions, KVN unit tags and signed time offsets. SGP4 numerical limits are 1 mm / 1e-5 m/s. Metadata IDs do not affect dynamics; the reference uses satnum0 for IDs its internal Alpha-5 encoding cannot represent.

128 independent CPython decimal fixtures cover leading-zero handling, and 129 additional finite exponent fixtures cover equivalent decimal forms, normal/subnormal boundaries, signed zero, severe underflow and values near maximum binary64. Numeric fixtures retain independently rounded expected values; tests allow up to three ULPs for the exponent cases while checking nonzero subnormals and zero signs explicitly. Parser tests reject missing/duplicate/incompatible fields, malformed numbers and overflow, and verify explicit defaults and output preservation. An extreme finite mean-motion initializer case verifies that an epoch arithmetic failure cannot publish a satellite.

Reference scripts, packages and raw outputs are in ignored `.validation/tinyomm/`; checked-in fixtures run offline without Python or reference libraries. References: [CelesTrak GP data formats](https://celestrak.org/NORAD/documentation/gp-data-formats.php), [python-sgp4](https://github.com/brandon-rhodes/python-sgp4).
